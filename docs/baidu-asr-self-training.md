# 百度语音自训练平台操作手册

用本厂的说法训练一个专用识别模型，解决专业词听错、「看下**上个月**的数据」被识别成「**三个月**」这类问题。

> 依据百度官方文档（2026-04 / 2026-05 版本，见文末「参考」）。平台现名「EasyDL 语音识别」，以控制台实际界面为准。

## 1. 先了解

- **短语音只能在「极速版」上训练**：要先在百度智能云开通「短语音识别极速版」，本系统 `.env` 设 `BAIDU_ASR_MODE=pro`。
- **费用**：语音技术下任一接口开通付费即可免费训练；识别调用按极速版计费（每个企业账号免费 5 万次，次数包 100 万次 3000 元，后付费约 4.2 元 / 千次）。
- **配额**：一个账号最多 10 个模型，同时只能训练 1 个、评估 1 个，最多上线 3 个。
- **上线要审核**：提交后人工审核 1~3 天，通过后上线再要 1~3 天，期间模型不能操作。
- **语料格式**：txt、**GBK 编码**、单文件 ≤5MB；热词（一行一个词）和句篇（一行一句）分开上传。

## 2. 准备测试集（必传）

平台用测试集算识别率，训练前后对比效果。

- **录音**：找几个车间同事，按平时的说法录几十到几百句。容易混的说法多录几条，如「看下上个月的数据」「近三个月的产量」「上上个月的回款」，以及常用客户名、物料名。
- **音频格式**：16k 采样、16bit、单声道 wav 或 pcm。
- **文件名**：只用字母和数字（不含中文、空格、特殊符号），如 `01.wav`、`02.wav`。
- **打包**：所有音频直接打成一个 zip（**不要放在文件夹里再压缩**），zip ≤100MB，解压后单个音频 ≤150MB。
- **标注文件**：txt、**GBK 编码**，每行 `文件名<Tab>正确文字`，单条 ≤5000 字：

  ```
  01.wav	看下上个月的数据
  02.wav	近三个月的产量是多少
  ```

- 基础模型在测试集上的识别率要 **>50%** 才能开始训练。

## 3. 导出训练语料

在项目里执行（需要能连业务库）：

```bash
cd server && npm run export-asr-corpus -- ../asr-out
```

生成两个 GBK 文件：

| 文件 | 平台里传到 | 内容 |
|------|-----------|------|
| `asr-corpus-hotwords.txt` | 热词 | 一行一个词：时间说法、菜单名、Agent 名、客户名（OCRD）、物料名（OITM） |
| `asr-corpus-sentences.txt` | 句篇 | 一行一句：「看下上个月的数据」等时间句式、Agent 快捷问法、BI 示例问法、用户改过的语音输入（`voice_logs.final_text`） |

- GBK 表示不了的行（emoji、生僻字）会跳过，超过 5MB 会截断，命令行会提示。
- **文件里有客户名和物料名，只传百度控制台，不要提交到仓库**（已 gitignore `asr-corpus*.txt`）。
- 实现：`server/scripts/export-asr-corpus.js`、`server/src/asr-corpus.js`。

## 4. 控制台操作

入口：<https://ai.baidu.com/smartasr/model>（左侧依次是「创建模型 → 训练模型 → 上线模型 → 模型调用」）

1. **创建模型**
   - 基础信息：产品类型选 **「短语音识别（16K）」**；填模型名称、行业（制造业）、场景、设备、功能描述（审核会参考，写清楚「工厂报表 / 生产数据语音查询」）、邮箱、联系方式。
   - 上传测试集：第 2 节的 zip 和标注文件。
   - 选择基础模型：选极速版（系统会按识别率推荐）。
2. **训练模型**
   - 上传第 3 节的热词文件和句篇文件（可以只传一种）→ 开始训练。
   - 训练完生成新版本，自动用测试集评估：字准率、句准率、插入、删除、替换。
   - 打开「评估详情」看哪些句子识别错了，针对性补语料再训一版；可以回退到历史版本。
3. **上线模型**：选效果最好的版本提交审核，等状态变成 **「上线完成」**。
4. **模型调用**：页面上有 **「模型ID」** 和 **「基础模型 pid」**，记下来。

## 5. 接入本系统

在 `server/.env`（Docker 部署用 `DEPLOY_ENV_FILE` 指定的文件）里填：

```bash
BAIDU_ASR_MODE=pro
BAIDU_ASR_LM_ID=<模型ID>
# 基础模型 pid 不是 80001 时才填
# BAIDU_ASR_DEV_PID=
```

重启服务生效。请求会走 `https://vop.baidu.com/pro_api`，带 `dev_pid` 与 `lm_id`（`server/src/baidu-asr.js`）。

## 6. 看效果、持续迭代

用户在对话框里改过的识别结果都记在 `voice_logs`：

```sql
-- 识别结果被用户改过的记录（= 识别错误样本）
SELECT TOP 200 created_at, user_code, recognized_text, final_text
FROM dbo.voice_logs
WHERE final_text IS NOT NULL AND final_text <> recognized_text
ORDER BY id DESC;
```

- 上线前后各取一段时间对比被改的比例。
- 有了新客户、新物料，或攒了一批改字记录后：重新导出语料 → 平台上迭代训练 → 上线新版本（模型 ID 不变则不用改 `.env`）。

## 7. 常见问题

- **上传语料后乱码 / 训练没效果**：确认文件是 GBK 编码（用本系统导出的就是）；Excel 或记事本另存时注意编码选「ANSI / GBK」。
- **不能选基础模型**：测试集上识别率低于 50%，检查录音格式（必须 16k 单声道）、标注是否和录音内容一致。
- **填了 lm_id 识别报错**：确认 `BAIDU_ASR_MODE=pro`、模型状态是「上线完成」、`BAIDU_ASR_DEV_PID` 与控制台的「基础模型 pid」一致。
- **服务器在百度云上**：可以把接口域名换成内网 `vop.baidubce.com` 省外网流量（需改 `baidu-asr.js` 里的地址）。
