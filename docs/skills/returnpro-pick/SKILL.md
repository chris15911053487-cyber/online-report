# 返工单领料

通过 `save_record` 工具调用后台返工单领料接口（B1 提交），**不直接写表**。
后台已将写入目标 `returnpro-pick` 配置为 API 动作，接口自带业务校验与领料日志。

## 工作流

1. 从用户话语中收集领料信息，缺什么问什么：
   - **返修单号**（docEntry，可选但建议提供）
   - 每行明细：**物料编码**（必填）、**数量**（必填，大于 0）、**仓库**（必填）、**批次号**（批次管理物料必填）
2. 信息齐全后，向用户复述一遍明细（单号、几行、每行物料/数量/仓库/批次）。
3. 调用 save_record，entity 固定为 "returnpro-pick"，payload_json 格式见 references/payload.md，例如：

```json
{
  "docEntry": 12345,
  "lines": [
    { "itemCode": "A001", "quantity": 2, "whsCode": "01", "batchNum": "B20260601" }
  ]
}
```

4. 工具会自动向用户出示确认卡片，用户确认后才真正提交；取消则不提交。
5. 转述结果：
   - 成功：告知"领料成功"及返回的单据号。
   - 失败：把接口返回的错误原样告知（如缺仓库、批次库存不足、B1 连接失败等），并提示如何补正。

## 注意

- 不要自行拼 SQL、不要猜测物料编码；编码不确定时让用户提供或先确认。
- 仓库（whsCode）每行必填，用户没说就要问。
- 一次对话可以多行明细，但都属于同一张返修单。
- 只能通过 save_record(entity="returnpro-pick") 提交，不要使用其他实体。
