# 预警与待办规则（管理员）

入口：管理后台 →「预警与待办」。一条规则 = 定时（或业务事件发生时）查一次数据，查到后有两种做法：

- **推送通知**：把查到的数据做成一张卡片，推给推送对象（个人收件箱 + 钉钉，可加钉钉群）。适合「出事了告诉大家」，如库存低于安全库存、销售额大幅下降。
- **生成待办**：每行数据一条待办，归到负责人名下，每天早上推汇总，处理完才结束。适合「这件事得有人去办」，如超期未完工的工单、待收货的采购单、待审批的单据。

规则表单里「查到数据后」切换两种做法。

## 和「定时报告」有什么不同

一句话：**预警与待办是「有事才找你」，定时报告是「到点就给你」**。

| | 预警与待办 | 定时报告 |
|---|---|---|
| 什么时候推 | 定时或业务事件（如报工保存）触发后先查数据，**查到符合条件的才推**，没事不打扰 | 到点**每次都推** |
| 内容怎么来 | 按规则判断（检查 SQL，或「命名查询 + 条件」），结果确定，**运行时不调 AI** | **AI 写**：Agent 按指令写报告，或读看板数据写 3~5 条要点 |
| 推送形式 | 推送通知（一张数据卡片），或生成待办（每行一件事，派给负责人，处理完才结束） | 一篇文字报告或要点，附看板链接 |
| 重点 | 发现异常、落实到人、跟踪到处理完 | 定期了解整体情况、趋势和总结 |
| 成本 | 只查数据库 | 每次调用大模型 |

怎么选：

- 想知道「**哪里出问题了**」→ 预警与待办的**推送通知**，如库存低于安全库存、本月客户销售额比上月掉了 30%、报工后不良率超过 5%。
- 想让「**谁去处理什么**」有人盯到底 → **生成待办**，如超期未完工的工单派给计划员、待收货的采购单、待审批的单据。
- 想定期收到「**整体情况怎么样**」→ 管理后台「定时报告」，如每天 8 点的生产日报、每周一的销售周报、看板每日要点，见《定时报告（管理员）》（含配置示例）。

几样常常一起用：日报看大盘，预警抓异常，待办盯落实。

## 生成待办：要准备什么数据

查询（检查 SQL，或「命名查询 + 条件」）每行是一件要办的事，必须带：

- **单据键列**：同一单据只生成一条待办，如 `DocNum`。数据里查不到这张单据了，待办自动关闭。
- **负责人列**：值是系统用户编码（登录用的 USER_CODE），如工单上的计划员。识别不了的（空、或不是系统用户）归为「未分配」，由主管转交。

可选：

- **到期日列**：如工单的计划完工日；没有就填「出现后几天内处理」（0 = 当天）。
- **超期几天告知主管**：超期达到这个天数，在主管早上的团队汇总里单列「超期升级」；留空不升级。

示例（超期未完工的工单；这里用工单创建人当负责人，实际请换成你们记录负责人的字段）：

```sql
SELECT T0.DocNum, T0.ItemCode, T0.DueDate, T1.USER_CODE AS Planner
FROM OWOR T0 LEFT JOIN OUSR T1 ON T1.USERID = T0.UserSign
WHERE T0.Status = 'R' AND T0.DueDate < GETDATE()
```

待办标题、说明、单据链接都可以用 `{列名}`，如标题 `工单 {DocNum} 已超期`，链接 `/report/work-orders`。

## 生成待办：主管与推送时间

规则的推送对象（用户或角色）就是这类待办的**主管**：在「消息 → 待办 → 团队」里能看到所有人的待办、转交未分配的；每天早上收一条团队汇总（周一附上周完成情况）。

推送时间（系统统一）：

- **早上 7:30**：先按最新数据同步所有待办规则，再给每个负责人推「今日待办」（没有待办不推），给主管推团队汇总；
- **下午 3:00**：再同步一次，今天到期 / 超期还没处理的再提醒负责人。

定时待办规则的 Cron 可以不填，只在这两个时间同步；填了就另外按这个频率同步（只更新列表，不推送）。事件触发的待办规则在事件发生时生成待办，并立刻通知新待办的负责人。

想现在看效果：规则列表上点「立即同步待办」（▶）会马上按当前数据生成并告诉你新增、关闭了几条；「立即推送待办汇总」会马上推一次早上的汇总（会真的发给负责人）。

## 待办的规则：以数据为准

- 负责人点「已处理」后，第二天同步时这张单据还在数据里，待办会**重新打开**；数据里查不到了才关闭。所以规则条件要写成「需要处理的单据」，处理掉就查不到。
- 负责人点「转交」后，负责人固定为转交对象，不再随数据变化。
- 停用、删除规则，或把它改回「推送通知」时，它生成的未处理待办一并关闭，处理记录保留。
- 一次最多处理 2000 行；超出时只新增和更新，不自动关闭，请收紧条件。

## 执行时间（Cron）怎么填

定时检查的规则、以及管理后台「定时报告」，都用 Cron 表达式设执行时间：5 段「分 时 日 月 周」，按中国时间。

- **看解读**：输入框下方会实时显示中文解读和接下来 3 次执行时间，如 `0 8 * * 1-5` →「工作日（周一至周五） 8:00 · 接下来：10/23 周五 08:00、…」。写错了会显示哪里有误；列表里也直接显示解读，鼠标停留可看原表达式。
- **AI 生成**：点输入框右边「AI 生成」，用一句话说什么时候执行（如「工作日早上 8 点半」「每 2 小时一次」），AI 写好表达式填进去，保存前看一眼下方解读对不对。也可以直接点下面的示例。
- **注意**：「日」和「周」同时写了具体值时要两个都满足才执行（如 `0 8 1 * 1` = 只在恰逢周一的 1 号），一般只写其中一个；「每月最后一天」这类写法不支持，AI 会提示改成最接近的写法。

常用写法：

| 表达式 | 含义 |
|------|------|
| `0 8 * * 1-5` | 工作日 8:00 |
| `30 7 * * *` | 每天 7:30 |
| `*/10 8-18 * * 1-5` | 工作日 8 点至 18 点每 10 分钟 |
| `0 */2 * * *` | 每 2 小时（整点） |
| `0 9 1 * *` | 每月 1 日 9:00 |

## 配置示例

下面的 SQL 和查询名只是示意，表和字段请按你们的 SAP B1 实际情况调整。验证方法：「命名查询 + 条件」可在表单里点「按当前数据试算」，只看结果、不推送；保存后在列表上点「测试触发」（▶）会按当前数据**真的执行一次**，查到就会推送，建议先把推送对象设成自己。

### 示例 1：库存低于安全库存（推送通知）

| 表单项 | 填写 |
|------|------|
| 规则名称 | 库存低于安全库存 |
| 查到数据后 | 推送通知 |
| 触发方式 | 定时检查，Cron `0 8,14 * * 1-5`（工作日 8:00、14:00） |
| 数据来源 | 检查 SQL（见下） |
| 去重键列名 | `ItemCode`（同一物料不重复推） |
| 冷却时间（分钟） | `1440`（同一物料一天内只推一次） |
| 推送对象 | 目标角色：仓库、采购 |
| 卡片标题 | `{ItemName} 库存不足` |
| 卡片正文 | 见下 |

检查 SQL：

```sql
SELECT ItemCode, ItemName, OnHand, MinLevel
FROM OITM
WHERE MinLevel > 0 AND OnHand < MinLevel AND frozenFor = 'N'
```

卡片正文（Markdown，`{列名}` 换成每行的值）：

```
- 物料：{ItemCode} {ItemName}
- 当前库存：{OnHand}
- 安全库存：{MinLevel}
```

SQL 返回行数大于 0 就推送，查不到不推。

### 示例 2：客户销售额比上月下降超过 20%（命名查询 + 条件）

数据来源选「命名查询 + 条件」，复用 BI 查询库里的查询，口径与看板一致，不用自己写 SQL：

```json
{
  "queryKey": "sales_by_customer",
  "params": { "period": "$thisMonth" },
  "conditions": [{ "column": "Amount", "op": "<=", "value": -20, "change": "pct" }],
  "match": "all",
  "compare": { "param": "period", "shift": -1 }
}
```

意思是：取本月各客户销售额，和上一期（上月）比，下降 20% 及以上的客户就提醒。卡片里可以用 `{Amount}`、`{Amount_prev}`（上月）、`{Amount_change_pct}`（变化百分比）。Cron 可填 `0 9 * * 1`（每周一 9:00）。

不会写 JSON 就点「一句话设预警」，说「本月有客户销售额比上月下降超过 20%，每周一 9 点提醒」，AI 起草并试算，确认后补推送对象再保存。

### 示例 3：超期未完工的工单（生成待办）

| 表单项 | 填写 |
|------|------|
| 规则名称 | 超期未完工工单 |
| 查到数据后 | 生成待办 |
| 触发方式 | 定时检查，Cron 留空（只在每天 7:30 汇总、15:00 复查前同步） |
| 检查 SQL | 见上文「生成待办：要准备什么数据」的示例 |
| 单据键列 | `DocNum` |
| 负责人列 | `Planner` |
| 到期日列 | `DueDate` |
| 超期几天告知主管 | `2` |
| 推送对象（主管） | 目标角色：生产主管 |
| 待办标题 | `工单 {DocNum} 已超期` |
| 待办说明 | `物料 {ItemCode}，计划完工 {DueDate}` |
| 单据链接 | `/report/work-orders` |

效果：每个计划员每天早上收到自己名下的超期工单；工单完工（数据里查不到）后待办自动关闭；超期 2 天还没处理的，在主管早上的团队汇总里单列出来。

### 示例 4：报工后不良率超标（事件触发）

触发方式选「事件触发」，事件名称 `pro-sign-save`（合并报工保存，事件字段有 `DocEntry`、`StepCode`、`UserCode` 等）。数据来源选「命名查询 + 条件」，前提是查询库里有一个按工单号查不良率的查询；参数里写 `"$event.DocEntry"`，用刚保存的工单号去查，条件写「不良率 > 5」。这样不用定时扫描，报工一保存就检查，超标马上推给质量主管。

## 统计与日志

- **待办统计**页签：近 7 / 30 / 90 天新增的待办，按负责人、按规则看完成率和超期率。完成 = 标了已处理或数据里已查不到；超期 = 完成晚于到期日，或至今未完成且已过到期日。
- **运行日志**页签：每次规则执行一行，最新的在上面。推送通知类显示「消息 / 钉钉 / 群」人数（进收件箱的人数 / 其中钉钉送达的人数 / 群 Webhook 数）；生成待办类显示「待办：新增 2，更新 5，关闭 1 …」；跳过、失败会写原因（如「所有数据在冷却期内」）。
  - 上方可**按规则、按状态筛选**（已发送 / 失败 / 跳过 / 已同步）。
  - **点一行看详情**：推送出去的卡片内容、收件人名单（谁已读、几点读的、钉钉是否送达 / 未绑定）、当时查到的数据（最多前 5 行）。钉钉显示「未绑定」的人只能在系统「消息 → 通知」里看到，请让他绑定钉钉。

## 推送通知（原警报）

推送通知类规则配置不变：检查 SQL 或命名查询 + 条件、去重键列与冷却时间（同一行在冷却期内不重复推）、推送对象（用户优先于角色）、群 Webhook、卡片标题 / 正文 / 按钮。「一句话设预警」用 AI 起草这类规则，详见《BI 看板管理》。
