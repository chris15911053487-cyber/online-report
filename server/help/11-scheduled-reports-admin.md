# 定时报告（管理员）

入口：管理后台 →「定时报告」→「新增推送任务」。到了设定的时间，AI 按你的指令查数据、写报告，推给指定的人：先进他们的「消息 → 通知」，再按渠道发钉钉 / 企微 / 飞书。

## 和「预警与待办」有什么不同

一句话：**定时报告是「到点就给你」，预警与待办是「有事才找你」**。

| | 定时报告 | 预警与待办 |
|---|---|---|
| 什么时候推 | 到点**每次都推** | 先查数据，**查到符合条件的才推**，没事不打扰 |
| 内容怎么来 | **AI 写**：按指令写报告，或读看板写 3~5 条要点 | 按规则判断，结果确定，运行时不调 AI |
| 推送形式 | 一篇文字报告或要点，附看板链接 | 一张数据卡片，或每人的待办（处理完才结束） |
| 重点 | 定期了解整体情况、趋势和总结 | 发现异常、落实到人、跟踪到处理完 |
| 成本 | 每次调用大模型 | 只查数据库 |

想定期收到「整体情况怎么样」用定时报告；想知道「哪里出问题了」或要「有人盯着处理」，用「预警与待办」，见《预警与待办规则（管理员）》。几样常常一起用：日报看大盘，预警抓异常，待办盯落实。

## 两种报告方式

表单里「报告方式」二选一：

- **AI 按指令写报告**：你写一段指令（Prompt 模板），AI 像在 AI 助手里一样查数据、写报告。可以关联一个 Skill，让 AI 知道该查哪些表、按什么口径算；不关联则按全局规则来。适合日报、周报、专题分析。
- **看板每日要点**：选一个关联了 BI 看板的 Agent，系统按看板筛选的默认值（如本月）取各卡片的数据，AI 写 3~5 条带数字的要点，附看板链接。每组推送对象按自己的角色取数，没权限看的卡片不会写进去。适合让管理层每天早上扫一眼，有兴趣再点进看板。

两种方式都可以在列表上点「手动触发」（▶）马上执行一次，**会真的推送**；看板要点在表单里还能点「预览要点（不推送）」，并选择按哪个角色的视角预览。

## 表单怎么填

- **任务名称**：会出现在推送标题里，如「每日生产日报」。
- **Cron 表达式**：什么时候执行，5 段「分 时 日 月 周」，中国时间。输入框下方实时显示中文解读和接下来 3 次执行时间；看不懂就点「AI 生成」，用一句话描述（如「工作日早上 8 点」）。详细写法见《预警与待办规则（管理员）》的「执行时间（Cron）怎么填」。
- **关联 Skill**（按指令写报告，可选）：下拉选择管理后台「AI Skill」里配好的 Skill，选中后下方显示它的说明；选「不关联」则按全局规则。Skill 告诉 AI 该查哪些表、按什么口径算，日报这类固定报告建议关联，结果更稳定，完整做法见下文「示例 1」。关联后这次报告**只用这一个 Skill**，且不受收件人角色限制（你选了就能用）；但 Skill 至少要勾选一个可用角色。Skill 停用、删除或没勾角色时，执行日志会记一条失败并写明原因，不会推出空报告。停用或已删除的 Skill 在下拉里会标出来，请换一个。
- **Prompt 模板**（按指令写报告）：说清楚统计什么时间范围、按什么分组、要哪些数字、输出什么格式。写得越具体，每天的报告越稳定。
- **关注点**（看板要点，可选）：如「重点关注大客户变化和退货」。
- **推送对象**：目标用户优先于目标角色。目标用户在搜索框里输入用户编码或姓名，从下拉里点选，可选多个；已选的显示为标签，点 × 移除。报告是**给每个人单独生成**的：AI 把收件人当作「当前用户」（用户编码、姓名、角色都是他本人的），所以指令或 Skill 里写「只看我负责的客户」这类按当前用户过滤的内容，每人收到的是自己的数据。人越多生成越慢、AI 调用越多，和个人无关的通用日报建议只选需要的人。
- **推送渠道**：`dingtalk`、`wecom`、`feishu`，多个用逗号分隔。不管填哪个，收件箱「消息 → 通知」里都会有一份。

列表上点「执行日志」可以看每次执行的结果和 AI 写出的内容。

## 看板每日要点：取数参数从哪来

定时报告表单里**不用、也没有地方填看板参数**。要点取数和你打开这个看板时看到的完全一样：

- 用看板「全局筛选」的**默认值**（如月份筛选 `period` 默认 `$thisMonth`）；
- 每张卡片的参数按看板里配好的来源取值（看板覆盖 > 图表固定值 > 同名筛选 > 查询默认），和看板页一致；
- 下拉筛选没写默认值时，取第一个选项。

这样做的好处是口径只维护一处：看板上看到的数字和每天推送的要点永远对得上。

**想改取数范围，就去改看板筛选的默认值**（管理后台 →「BI 看板管理」→ 看板 → 全局筛选），并且**用动态值，不要写死日期**。每天执行时按当天的中国日期自动换算：

| 动态值 | 含义（以 2026-10-22 执行为例） |
|------|------|
| `$today` / `$yesterday` | 今天 2026-10-22 / 昨天 2026-10-21 |
| `$thisMonth` / `$lastMonth` | 本月 2026-10 / 上月 2026-09 |
| `$monthStart` / `$yearStart` | 本月 1 日 2026-10-01 / 今年 1 月 1 日 2026-01-01 |
| `$thisYear` / `$lastYear` | 今年 2026 / 去年 2025 |

如果写死成 `2026-10`，到了 11 月要点还在说 10 月的数据。

**同一套图表要按不同时间范围推送**（如看板平时看本月，但每月 1 号想推上月总结），不要改原看板，而是：

1. 「BI 看板管理」里新建一个看板，「添加图表」引用原来那些图表（图表可被多个看板复用，不用重做），全局筛选同名（如 `period`），默认值改成 `$lastMonth`；
2. 「Agent 配置」里新建一个 Agent 关联这个新看板，可见角色与原 Agent 一致；
3. 定时报告里选这个 Agent。

**权限照常生效**：每组推送对象按自己的角色取数，没权限的卡片不会写进要点；卡片查询用到当前登录人（如「我的客户」）时，按每个人分别取数、分别写要点。

**检查**：保存前点「预览要点（不推送）」，可以按某个角色的视角预览，确认 AI 讲的是你想要的时间范围和卡片。

## 配置示例

下面的指令只是示意，请按你们实际的业务口径和 Skill 调整。

### 示例 1：每日销售订单日报（关联 Skill，可直接照做）

这个例子只用 SAP B1 标准表 `ORDR`（销售订单）和 `OCRD`（业务伙伴），各家账套都有，照着填就能跑通。分两步：先建 Skill（告诉 AI 查哪些表、按什么口径），再建定时报告（告诉 AI 这次要什么）。

**第 1 步：管理后台 →「AI Skill」→ 新增**

省事的做法：点「AI 新建」，用一句话说需求（如「每天的销售订单日报：昨天的订单数、金额、客户数和前天对比，昨天下单金额前 5 的客户，已过交货日期仍未清的订单」）。AI 会读真实表结构，写出和下面一样格式的正文，每条查询都先在库里试跑通过，「允许的表」也自动填好；你只需检查口径、勾选角色、保存。也可以按下表手工填：

| 字段 | 填写 |
|------|------|
| 名称 | `sales-order-daily`（小写字母、数字、横线） |
| 描述 | 销售订单日报：只查 ORDR / OCRD，金额用 DocTotal，排除已取消订单 |
| 可使用此 Skill 的角色 | 至少勾一个，如「销售主管」（不选 = 仅管理员，定时报告会执行失败） |
| 允许的表 | `ORDR, OCRD`（AI 查别的表会被系统拦下） |
| 启用 | 勾选 |

正文：

````
# 销售订单日报

## 用到的表
- ORDR 销售订单表头：DocNum 单号、DocDate 单据日期、DocDueDate 交货日期、
  CardCode 客户编码、CardName 客户名称、DocTotal 含税总额（本币，元）、
  CANCELED（'Y' 已取消）、DocStatus（'O' 未清、'C' 已清）
- OCRD 业务伙伴：CardCode、CardName、CardType（'C' 客户）

## 口径
- 一律排除已取消：CANCELED = 'N'
- 金额用 DocTotal，报告里换算成「万元」保留 2 位
- 「今天」按中国时间：CAST(DATEADD(HOUR,8,SYSUTCDATETIME()) AS DATE)，
  「昨天」再减 1 天；不要用 GETDATE()

## 查询模式（照这几条写，只改日期和 TOP 数量）
1. 昨天与前天汇总（订单数、金额、客户数）：
   WITH d AS (SELECT CAST(DATEADD(DAY,-1,DATEADD(HOUR,8,SYSUTCDATETIME())) AS DATE) AS 昨天)
   SELECT CASE WHEN T0.DocDate = d.昨天 THEN N'昨天' ELSE N'前天' END AS 日期,
          COUNT(1) AS 订单数, SUM(T0.DocTotal) AS 金额, COUNT(DISTINCT T0.CardCode) AS 客户数
   FROM ORDR T0 CROSS JOIN d
   WHERE T0.CANCELED = 'N' AND T0.DocDate IN (d.昨天, DATEADD(DAY,-1,d.昨天))
   GROUP BY CASE WHEN T0.DocDate = d.昨天 THEN N'昨天' ELSE N'前天' END
2. 昨天下单金额前 5 的客户：
   SELECT TOP 5 T0.CardCode AS 客户编码, T1.CardName AS 客户名称,
          COUNT(1) AS 订单数, SUM(T0.DocTotal) AS 金额
   FROM ORDR T0 JOIN OCRD T1 ON T0.CardCode = T1.CardCode
   WHERE T0.CANCELED = 'N'
     AND T0.DocDate = CAST(DATEADD(DAY,-1,DATEADD(HOUR,8,SYSUTCDATETIME())) AS DATE)
   GROUP BY T0.CardCode, T1.CardName ORDER BY 金额 DESC
3. 已过交货日期仍未清的订单：
   SELECT T0.DocNum AS 单号, T0.CardName AS 客户, T0.DocDueDate AS 交货日期, T0.DocTotal AS 金额
   FROM ORDR T0
   WHERE T0.CANCELED = 'N' AND T0.DocStatus = 'O'
     AND T0.DocDueDate < CAST(DATEADD(HOUR,8,SYSUTCDATETIME()) AS DATE)
   ORDER BY T0.DocDueDate

## 输出
先 3 句话结论（金额、和前天比的变化、最需要关注的一件事），再给表格；
查不到数据就直说「昨天没有销售订单」，不要编数字。
````

**第 2 步：管理后台 →「定时报告」→ 新增推送任务**

| 表单项 | 填写 |
|------|------|
| 任务名称 | 每日销售订单日报 |
| 报告方式 | AI 按指令写报告 |
| Cron | `0 8 * * 1-6`（周一至周六 8:00） |
| 关联 Skill | `sales-order-daily`（选中后下方显示上面的描述） |
| 目标角色 | 销售主管 |
| 推送渠道 | `dingtalk` |

Prompt 模板：

```
写昨天的销售订单日报：
1. 昨天的订单数、金额（万元）、客户数，和前天对比，变化超过 20% 要指出；
2. 昨天下单金额前 5 的客户；
3. 已过交货日期仍未清的订单，最多列 10 张，按交货日期从早到晚。
```

**第 3 步：验证**。保存后在列表上点「手动触发」（▶，会真的推送，可先把目标用户改成自己），再点「执行日志」看 AI 写出的内容。推出来大致是：

```
每日销售订单日报
昨天共 23 张销售订单，金额 86.40 万元，比前天多 18%；客户 A 一家下单 21.30 万元，占四分之一。
有 4 张订单已过交货日期仍未清，最早的已拖 9 天，需要跟进。

| 日期 | 订单数 | 金额（万元） | 客户数 |
| 昨天 | 23 | 86.40 | 15 |
| 前天 | 19 | 73.20 | 13 |
……
```

（数字为示意，以你们的数据为准。）跑不通时按执行日志排查：写着「不存在或已停用」「没有设置可用角色」就回 Skill 页改；AI 说某张表不允许查询，说明正文里写了白名单外的表，把表加进白名单或改正文。

### 示例 4：销售看板每日要点（本月至今）

前提：BI 看板「销售看板」的全局筛选有月份筛选 `period`，默认值 `$thisMonth`；卡片有「本月净销售额」KPI、「客户销售额前 10」表格、「退货金额」等；Agent「销售分析」（`sales`）关联了这个看板。

| 表单项 | 填写 |
|------|------|
| 任务名称 | 销售看板每日要点 |
| 报告方式 | 看板每日要点 |
| Cron | `30 8 * * 1-5`（工作日 8:30） |
| 看板（关联看板的 Agent） | 销售分析（看板 sales） |
| 关注点 | 重点关注大客户变化和退货 |
| 目标角色 | 销售、销售主管 |

推送效果类似：

```
销售看板每日要点
1. 本月净销售额 326 万，已完成月目标的 68%，比上月同期多 12%。
2. 大客户 A 本月 18 万，比上月同期少 35%，是降幅最大的客户。
3. 本月退货 4.2 万，占销售额 1.3%，主要来自物料 X。
查看看板：https://…/agents/sales
```

销售和销售主管各按自己的角色取数，看到的卡片不同，要点也会不同。

### 示例 5：每月 1 号推上月销售回顾

1 号当天本月几乎没有数据，按示例 4 的看板推出来没有意义，所以单独配一个「上月」视角：

1. BI 看板管理 → 新建看板「销售月度回顾」（`sales_monthly`）：全局筛选 `period`（月份），默认值 **`$lastMonth`**；「添加图表」选和销售看板相同的那几张图表。
2. Agent 配置 → 新建 Agent「销售月度回顾」（`sales-monthly`），关联看板 `sales_monthly`，可见角色：销售主管、总经理。
3. 定时报告 → 新增推送任务：

| 表单项 | 填写 |
|------|------|
| 任务名称 | 上月销售回顾 |
| 报告方式 | 看板每日要点 |
| Cron | `0 9 1 * *`（每月 1 日 9:00） |
| 看板（关联看板的 Agent） | 销售月度回顾（看板 sales_monthly） |
| 关注点 | 和前一个月对比，指出变化最大的客户和产品 |
| 目标角色 | 销售主管、总经理 |

11 月 1 日执行时，`$lastMonth` 自动算成 2026-10，要点讲的就是 10 月全月。

### 示例 6：每天早上推昨日生产要点

前提：生产看板的全局筛选是日期筛选 `bizDate`，默认值 **`$yesterday`**（看板页打开默认看昨天）。定时报告选关联生产看板的 Agent，Cron `0 8 * * 1-6`（周一至周六 8:00），关注点「不良率和未按期完工」，推给生产主管。每天 8 点推的就是前一天的完工、不良和延期情况。

## 注意

- 每次执行都会调用大模型，频率别设太高；日报、周报一般一天或一周一次就够。
- 「出问题才提醒」的需求（如库存不足、销售额大跌）不要用定时报告每天去找，改用「预警与待办」，没问题时不打扰人，也不花 AI 费用。
- 看板要点里的链接需要服务器配置公网地址（`PUBLIC_BASE_URL`）；没配置时推送里只提示到系统里打开看板。
