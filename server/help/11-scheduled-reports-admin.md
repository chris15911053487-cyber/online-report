# 定时报告（管理员）

入口：管理后台 →「定时报告」→「新增推送任务」。到了设定的时间，AI 按你的指令查数据、写报告，推给指定的人：先进他们的「消息 → 通知」，再按渠道发钉钉 / 企微 / 飞书。

## 和「预警与待办」有什么不同

一句话：**定时报告是「到点就给你」，预警与待办是「有事才找你」**。

| | 定时报告 | 预警与待办 |
|---|---|---|
| 什么时候推 | 到点**每次都推** | 先查数据，**查到符合条件的才推**，没事不打扰 |
| 内容怎么来 | **AI 写**：按指令写报告，或读看板写 3~5 条要点 | 按规则判断，结果确定，运行时不调 AI |
| 推送形式 | 一篇文字报告或要点，附看板链接 | 一张数据卡片，或每人的待办（处理完才结束） |
| 重点 | 定期了解整体情况、趋势和总结 | 发现异常、落实到人、跟踪到处理完 |
| 成本 | 每次调用大模型 | 只查数据库 |

想定期收到「整体情况怎么样」用定时报告；想知道「哪里出问题了」或要「有人盯着处理」，用「预警与待办」，见《预警与待办规则（管理员）》。几样常常一起用：日报看大盘，预警抓异常，待办盯落实。

## 两种报告方式

表单里「报告方式」二选一：

- **AI 按指令写报告**：你写一段指令（Prompt 模板），AI 像在 AI 助手里一样查数据、写报告。可以关联一个 Skill，让 AI 知道该查哪些表、按什么口径算；不关联则按全局规则来。适合日报、周报、专题分析。
- **看板每日要点**：选一个关联了 BI 看板的 Agent，系统按看板筛选的默认值（如本月）取各卡片的数据，AI 写 3~5 条带数字的要点，附看板链接。每组推送对象按自己的角色取数，没权限看的卡片不会写进去。适合让管理层每天早上扫一眼，有兴趣再点进看板。

两种方式都可以在列表上点「手动触发」（▶）马上执行一次，**会真的推送**；看板要点在表单里还能点「预览要点（不推送）」，并选择按哪个角色的视角预览。

## 表单怎么填

- **任务名称**：会出现在推送标题里，如「每日生产日报」。
- **Cron 表达式**：什么时候执行，5 段「分 时 日 月 周」，中国时间。输入框下方实时显示中文解读和接下来 3 次执行时间；看不懂就点「AI 生成」，用一句话描述（如「工作日早上 8 点」）。详细写法见《预警与待办规则（管理员）》的「执行时间（Cron）怎么填」。
- **关联 Skill**（按指令写报告，可选）：下拉选择管理后台「AI Skill」里配好的 Skill，选中后下方显示它的说明；选「不关联」则按全局规则。Skill 告诉 AI 该查哪些表、按什么口径算，日报这类固定报告建议关联，结果更稳定。停用或已删除的 Skill 会标出来，请换一个。
- **Prompt 模板**（按指令写报告）：说清楚统计什么时间范围、按什么分组、要哪些数字、输出什么格式。写得越具体，每天的报告越稳定。
- **关注点**（看板要点，可选）：如「重点关注大客户变化和退货」。
- **推送对象**：目标用户优先于目标角色；目标用户多个用逗号分隔，填系统用户编码（如 `U001, U002`）。
- **推送渠道**：`dingtalk`、`wecom`、`feishu`，多个用逗号分隔。不管填哪个，收件箱「消息 → 通知」里都会有一份。

列表上点「执行日志」可以看每次执行的结果和 AI 写出的内容。

## 看板每日要点：取数参数从哪来

定时报告表单里**不用、也没有地方填看板参数**。要点取数和你打开这个看板时看到的完全一样：

- 用看板「全局筛选」的**默认值**（如月份筛选 `period` 默认 `$thisMonth`）；
- 每张卡片的参数按看板里配好的来源取值（看板覆盖 > 图表固定值 > 同名筛选 > 查询默认），和看板页一致；
- 下拉筛选没写默认值时，取第一个选项。

这样做的好处是口径只维护一处：看板上看到的数字和每天推送的要点永远对得上。

**想改取数范围，就去改看板筛选的默认值**（管理后台 →「BI 看板管理」→ 看板 → 全局筛选），并且**用动态值，不要写死日期**。每天执行时按当天的中国日期自动换算：

| 动态值 | 含义（以 2026-10-22 执行为例） |
|------|------|
| `$today` / `$yesterday` | 今天 2026-10-22 / 昨天 2026-10-21 |
| `$thisMonth` / `$lastMonth` | 本月 2026-10 / 上月 2026-09 |
| `$monthStart` / `$yearStart` | 本月 1 日 2026-10-01 / 今年 1 月 1 日 2026-01-01 |
| `$thisYear` / `$lastYear` | 今年 2026 / 去年 2025 |

如果写死成 `2026-10`，到了 11 月要点还在说 10 月的数据。

**同一套图表要按不同时间范围推送**（如看板平时看本月，但每月 1 号想推上月总结），不要改原看板，而是：

1. 「BI 看板管理」里新建一个看板，「添加图表」引用原来那些图表（图表可被多个看板复用，不用重做），全局筛选同名（如 `period`），默认值改成 `$lastMonth`；
2. 「Agent 配置」里新建一个 Agent 关联这个新看板，可见角色与原 Agent 一致；
3. 定时报告里选这个 Agent。

**权限照常生效**：每组推送对象按自己的角色取数，没权限的卡片不会写进要点；卡片查询用到当前登录人（如「我的客户」）时，按每个人分别取数、分别写要点。

**检查**：保存前点「预览要点（不推送）」，可以按某个角色的视角预览，确认 AI 讲的是你想要的时间范围和卡片。

## 配置示例

下面的指令只是示意，请按你们实际的业务口径和 Skill 调整。

### 示例 1：每日生产日报

| 表单项 | 填写 |
|------|------|
| 任务名称 | 每日生产日报 |
| 报告方式 | AI 按指令写报告 |
| Cron | `0 8 * * 1-6`（周一至周六 8:00） |
| 关联 Skill | 下拉选生产相关的 Skill |
| 目标角色 | 生产主管、厂长 |
| 推送渠道 | `dingtalk` |

Prompt 模板：

```
统计昨天的生产完工情况：
1. 按工序汇总完工数量、报工人数，列出完工最多的 5 个工单；
2. 和前一天对比，变化超过 20% 的工序单独指出；
3. 列出昨天应完工但还没完工的工单（工单号、物料、计划完工日）。
用简洁的 Markdown 输出，先给 3 句话结论，再给表格。
```

### 示例 2：每周销售周报

| 表单项 | 填写 |
|------|------|
| 任务名称 | 销售周报 |
| 报告方式 | AI 按指令写报告 |
| Cron | `0 9 * * 1`（每周一 9:00） |
| 目标用户 | 销售总监、总经理的用户编码 |
| 推送渠道 | `dingtalk, wecom` |

Prompt 模板：

```
统计上周（周一到周日）的销售情况：总销售额、订单数，与再上一周对比；
按客户列出销售额前 10 名，标出比上周下降超过 30% 的客户；
最后给出 2~3 条需要关注的事项。
```

### 示例 3：销售看板每日要点（本月至今）

前提：BI 看板「销售看板」的全局筛选有月份筛选 `period`，默认值 `$thisMonth`；卡片有「本月净销售额」KPI、「客户销售额前 10」表格、「退货金额」等；Agent「销售分析」（`sales`）关联了这个看板。

| 表单项 | 填写 |
|------|------|
| 任务名称 | 销售看板每日要点 |
| 报告方式 | 看板每日要点 |
| Cron | `30 8 * * 1-5`（工作日 8:30） |
| 看板（关联看板的 Agent） | 销售分析（看板 sales） |
| 关注点 | 重点关注大客户变化和退货 |
| 目标角色 | 销售、销售主管 |

推送效果类似：

```
销售看板每日要点
1. 本月净销售额 326 万，已完成月目标的 68%，比上月同期多 12%。
2. 大客户 A 本月 18 万，比上月同期少 35%，是降幅最大的客户。
3. 本月退货 4.2 万，占销售额 1.3%，主要来自物料 X。
查看看板：https://…/agents/sales
```

销售和销售主管各按自己的角色取数，看到的卡片不同，要点也会不同。

### 示例 4：每月 1 号推上月销售回顾

1 号当天本月几乎没有数据，按示例 3 的看板推出来没有意义，所以单独配一个「上月」视角：

1. BI 看板管理 → 新建看板「销售月度回顾」（`sales_monthly`）：全局筛选 `period`（月份），默认值 **`$lastMonth`**；「添加图表」选和销售看板相同的那几张图表。
2. Agent 配置 → 新建 Agent「销售月度回顾」（`sales-monthly`），关联看板 `sales_monthly`，可见角色：销售主管、总经理。
3. 定时报告 → 新增推送任务：

| 表单项 | 填写 |
|------|------|
| 任务名称 | 上月销售回顾 |
| 报告方式 | 看板每日要点 |
| Cron | `0 9 1 * *`（每月 1 日 9:00） |
| 看板（关联看板的 Agent） | 销售月度回顾（看板 sales_monthly） |
| 关注点 | 和前一个月对比，指出变化最大的客户和产品 |
| 目标角色 | 销售主管、总经理 |

11 月 1 日执行时，`$lastMonth` 自动算成 2026-10，要点讲的就是 10 月全月。

### 示例 5：每天早上推昨日生产要点

前提：生产看板的全局筛选是日期筛选 `bizDate`，默认值 **`$yesterday`**（看板页打开默认看昨天）。定时报告选关联生产看板的 Agent，Cron `0 8 * * 1-6`（周一至周六 8:00），关注点「不良率和未按期完工」，推给生产主管。每天 8 点推的就是前一天的完工、不良和延期情况。

## 注意

- 每次执行都会调用大模型，频率别设太高；日报、周报一般一天或一周一次就够。
- 「出问题才提醒」的需求（如库存不足、销售额大跌）不要用定时报告每天去找，改用「预警与待办」，没问题时不打扰人，也不花 AI 费用。
- 看板要点里的链接需要服务器配置公网地址（`PUBLIC_BASE_URL`）；没配置时推送里只提示到系统里打开看板。
